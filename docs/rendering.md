# 写实渲染

## 当前实现

- 原作的外部拼片、道路、标识和吊机位置继续由 `dist/scene.js` 定义。
- 玻璃为 45 mm 厚的封闭体，具有两个光学界面、透射、折射和颜色吸收。镜面棱面片兼有反射与透射。
- 框架为带倒角的矩形截面，保留磁力连接件。家具增加圆角、分离坐垫；主楼设置客厅、书房和卧室，室内楼梯对应的楼板有开口。
- `three-gpu-pathtracer` 在视角静止后累积计算；拖动时显示快速预览。最多累积 192 个样本，完成后暂停采样。
- 环境照明使用柔化后的 HDR，背景仍使用原始全景；室内采用面光源。
- 完整 HDR 渲染结果送入本地 WebGPU OIDN 降噪。计算结果转成清晰画面展示，不会把旧视角的画面应用到新视角。
- 缺少 WebGPU 的设备保留空间滤波方式。界面准备及细化状态不等同于宣称已达到参考图的照片级质量。

## 构建和资源

安装或更新代码依赖后运行 `npm ci`、`npm run build`，预览仍使用 `npm start`。

渲染器和几何工作线程位于 `dist/vendor/`，ONNX 运行时位于 `dist/vendor/ort/`，模型权重位于 `dist/assets/denoiser/`。运行过程没有将渲染图片发送到远程服务。

OIDN 浏览器适配源固定为 `scripts/vendor/denoiser/UPSTREAM.md` 中的提交。npm 上的旧版 `denoiser` 是不同 API，不能直接替换。ONNX Runtime 固定为 1.27.0 的 WebGPU 构建，对应 asyncify 运行文件。当前使用无辅助通道的 HDR 模型；如扩展法线/反照率辅助通道，需同步提供对应权重并验证。

## 验证

`npm test` 包含：原作构件和道路检查、楼梯连接、几何有效性、玻璃入射与出射界面、实例转为静态几何后的位置和颜色保持、楼板开口，以及本地运行资源完整性。

浏览器验收需等待实际清晰图产生，再检查全景与室内、转动、日夜切换以及快速/写实切换。不可仅根据按钮状态或初始化成功认定视觉效果合格。
